Bringing History in line with Home

Home's Timeline redesign (docs/log/49–52) settled on a visual language — thin-rule day dividers, a leading time column, a muted pill for state — that History never picked up. It still reads as an older screen: bold text headers, trailing timestamps, two boxy icon buttons per row. Below is that same language applied to History, using WellTrack's real tokens (light and dark), followed by what changed and why, and some general notes on the app beyond this one screen.

What changed, and why

Six moves, each one already established on Home — nothing invented for History specifically.

1

Day headers become dividers frontend

CollapsibleSection's bold-text-plus-chevron header is replaced with the same thin-rule-plus-pill divider every Home day group already uses — one visual language for "a new day starts here," not two.

2

Time leads the row frontend

Home always puts the time first, in a tabular-nums column, so a list of rows reads as a scannable timeline. History currently buries it as a small trailing line under the label — moved to match.

3

The value becomes a pill backend

GET /api/history currently returns one pre-joined string, "Sertraline: Done" — the exact thing HistoryPage.tsx's own comment already flags as wanting "a real field on the response instead." Splitting it into categoryName + a formatted value is what lets the value render as its own pill, the same way a Timeline row's "Logged"/"Done" state does — small, additive, and the formatting logic (formatCategoryLogValue) already exists in history.ts, just needs to stop being concatenated before it's sent.

4

Pill color means outcome, not "is a pill" frontend

"Done" gets Home's exact success-green pill — it means the same thing "Logged" does. "Not done" and every numeric/scale/duration value stay neutral: an explicit "no," or a plain recorded number, isn't a failure the way a missed reminder is, so it shouldn't borrow danger red just because it's a pill.

5

A category icon, when there is one backend

Home already shows a reminder's category icon; History's category is already the same table, just not currently selected in this one query. One more field on the same include.

6

Edit/Delete shrink to match Home's own icon buttons frontend

The current pair are full Button components with borders and padding sized for a primary action. Home's own row-level icon button (Timeline's "+") is a quiet 28px circle — Edit/Delete adopt that same restrained sizing instead of visually competing with the row's own content.

General UI notes for the app

Beyond this one screen — things that would tighten the whole product, roughly in order of how much they'd be felt.

🧭One state-pill vocabulary, everywhere

Timeline now has three separate pill palettes (PILL_TONE, TASK_PILL_TONE, and whatever History grows next) that happen to agree today because they were copied by hand. Worth pulling into one shared StatusPill component/token map before a third or fourth screen needs its own — the risk isn't visual, it's that "success" quietly drifts to a different green in one spot after a future edit nobody thought to check against the other two.

🌓Spot-check dark mode as its own pass

The app's dark palette is well-built (real tokens, not an inverted filter) — but it's easy for a new component to get built and eyeballed in light mode only, the way the value pill above would be if I hadn't checked color-scheme both ways. A quick "toggle dark, scroll every page" pass after each visual change catches this cheaply.

🫥Empty and loading states are half the app

"Loading…" as bare text and "Nothing to show yet" as one plain line both work, but neither matches the polish of a populated row. Even a simple skeleton row (a muted rounded rectangle, Timeline's own row shape with no content) reads as "the app is working," where bare text reads as "the app forgot to finish this screen" for the half-second it's visible.

👆Row tap-targets vs. row actions

Timeline solved "a button inside a button is invalid HTML" by making the checkbox and the row body siblings (see TaskRowItem). History's Edit/Delete pair should follow the exact same shape once restyled — two adjacent 28px circles beside the row, not nested inside a bigger tappable card, so a stray tap on the row itself doesn't compete with either action.

📏A second breakpoint between mobile and md:

History's own container comment already flags this: content that's genuinely single-column stays cramped-then-suddenly-wide at the md: jump, because nothing happens between 412px and 768px. A small step at sm: (already used for ActionButton's icon-to-label swap) for spacing/padding alone — not a layout change — would smooth that jump on the tablet-width sliver in between.

🔔Let a pill answer "should I do something," not just "what happened"

Overdue (red) and Done (green) on a Task row work because they're actionable at a glance. History's pills are purely retrospective — that's correct for a log, but worth keeping deliberate: a future screen that reuses the same pill component for something the user still needs to act on should stay visually distinct from "this already happened," or the whole vocabulary stops being trustworthy at a glance.
