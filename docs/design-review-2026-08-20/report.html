Summary

A calm, disciplined app that stalls at the moment it should delight

WellTrack's bones are good. The visual language is quiet and consistent on purpose — no gamified streak badges, no alarmist color on a symptom severity chart, copy that repeatedly refuses to imply diagnosis or causation. For an app aimed at people managing chronic conditions, that restraint is the correct call, and it's applied consistently across every screen, not just the marketing copy.

What's missing is the layer users now expect by default from any web app, health-related or not: state that confirms itself instantly instead of a few seconds late, feedback that fades instead of accumulating on screen forever, empty states that coach rather than just announce, and a settings page that doesn't waste three-quarters of a desktop monitor. None of the gaps below are exotic — they're the table stakes a 2026 user has absorbed from every app they already use daily.

✓ Already meets the bar

  • Mobile bottom nav / desktop top nav split, done properly
  • Consistent collapsible-section language across every page
  • Docked Quick Add — survives scroll without colliding with content
  • Calm, non-alarmist tone; no gamification pressure
  • Real keyboard/focus and touch-target accessibility work

✗ Falls short of 2026 norms

  • Success feedback that never disappears, and lags reality by up to 10s
  • Charts that give a single point the same canvas as thirty
  • Desktop Settings and History ignore two-thirds of the viewport
  • Editing works in one view and is a dead button in another
  • No dark mode, export, or reminders — now default expectations
01 — Feedback & motion

Confirmations that overstay, and a summary that lies for ten seconds

Modern apps confirm an action once, briefly, then get out of the way. WellTrack confirms it permanently, and in one specific case, confirms it late.

Correction

"Saved" messages never leave — this finding was wrong

Update: this was a misdiagnosis, corrected after implementation review. The app already had a self-clearing useTimedMessage hook (4-second auto-clear), committed a full day before this review ran. The verification script that produced the screenshot below logged four entries within 1–2 seconds of each other and screenshotted almost immediately after — well inside every message's 4-second window — so the messages never had a chance to actually clear before being observed. Building a toast/snackbar system to "fix" this would have reversed a deliberate, accessibility-motivated decision already recorded in this project's own implementation log. Left here, corrected rather than deleted, as the original claim below.

Every Quick Add write leaves a permanent green "Mood entry saved." line sitting above the entry, indefinitely — it's still there after four more entries, a page reload cycle, anything short of a hard refresh. It reads less like a confirmation and more like a growing log of receipts glued to the page.

Gap

The headline summary doesn't know what just happened

The top "Today" card polls on a 10-second interval, independent of the four Quick Add sections below it. Log a mood entry and the section directly underneath updates instantly — the card above it, three inches away, keeps insisting "Nothing logged yet today" for up to ten more seconds. Two pieces of the same screen visibly disagree about the same fact.

What a modern app does: one successful write invalidates every view of that data on screen, not just the section that made the call — a shared cache/event bus, not independent polling loops with different clocks.
Nice to have

Deleting an entry drops to a native browser dialog

Delete is guarded by window.confirm() — the plain OS-styled "This page says..." box, not a component that matches anything else on the page. It works, but it's the one moment in the whole app that visibly steps outside WellTrack's own design system.

What a modern app does: reuses its own dialog component for a destructive confirmation, keeping tone and styling consistent with everything else the user has seen.
02 — Data at a glance

Charts built for thirty days, shown after one

Trends is the app's most data-forward screen, and the one most exposed by a new account's natural sparse-data state.

Gap

One data point gets the same canvas as thirty

With a single day logged, both line charts render one dot pinned to the far right edge of an otherwise empty plot — no gridlines, no shaded range, nothing signaling "this chart works, you just haven't given it much to draw yet." It reads like something failed to load rather than like an honest, expected early state.

What a modern app does: a dedicated sparse-data treatment — "Log a few more days to see a trend line" over a friendly placeholder curve — distinct from both the loading state and the real chart.
03 — Layout & space

Two screens forgot they have a desktop

Dashboard and Trends both widen into real two-column layouts once there's room. History and Settings don't get the memo.

Gap

Settings pins itself to a 384px column on a 1440px screen

Every card on Settings is capped by the same fixed-width component used for a login form — appropriate for a single centered form, less so for a page with three independent sections stacked vertically while roughly two-thirds of the browser window sits empty beside them.

What a modern app does: either a genuinely centered, comfortably-wide single column (600–700px), or lets independent sections like Profile / Security / Danger zone sit side by side once there's room, the way Dashboard's own panels already do.
04 — Editing your own data

Edit works, just not from the page called History

The most surprising finding in this review, because the working version already exists elsewhere in the same app.

Gap

A permanently disabled Edit button, on the one page built for browsing everything

On Dashboard, each entry's own section card has a working Edit button, wired to the same form used to create it. On History — the page explicitly framed as "browse everything you've logged" — every Edit button is disabled, with a tooltip reading "Editing is coming soon." A user correcting a typo in a symptom note has to know to leave the page they're looking at data on and go find the same entry back on Dashboard instead.

What a modern app does: one edit affordance, reachable everywhere that entry is shown — or if scope genuinely requires staging it, the disabled state explains itself in-context rather than pointing the user to hunt for the working version elsewhere.
05 — Table stakes

A handful of defaults 2026 users no longer think of as optional

None of these are unique to WellTrack's category — they're baseline expectations carried in from every other app on the same phone.

Nice to have

No dark mode, despite the theming already being token-based

Every color in this codebase already routes through named Tailwind theme tokens (--color-brand, --color-surface, and so on) rather than one-off hex values scattered through components — which is exactly the groundwork a dark palette needs. The remaining work is a second token set and a preference switch, not a redesign.

Nice to have

Nothing brings the user back

A habit/symptom tracker's entire value compounds with consistent daily logging, and nothing in the app currently prompts that — no reminder notification, no daily-digest email, no "you usually log around 6pm" nudge. The streak counter on Dashboard quietly assumes the user remembers on their own.

Nice to have

No way out with your own data

Delete account is implemented carefully — typed confirmation, clear irreversibility warning. There's no equivalent "export everything first" option next to it, which matters more, not less, for health data a person might want to hand to a clinician or simply keep.

✓

The responsive foundation is already doing real work. The bottom-nav/top-nav split, the collapsible sections repeated consistently across Dashboard, Trends, History, and Settings, and a Quick Add button that's actually docked into the nav bar instead of floating over content — these solve real, previously-shipped bugs, not hypothetical ones.

✓

The tone is disciplined in a way that matters for this audience. No gamified streak pressure, no color-coded alarm on a symptom chart, copy that repeatedly declines to imply diagnosis or causation — this is a harder restraint to maintain than it looks, and it holds up on every screen checked.

If I had to pick three

Ranked by how much a user would actually notice

First

Make Edit consistent between Dashboard and History

The working version already exists — this is wiring the same form into a second entry point, not building new functionality. Highest ratio of user-facing impact to actual engineering effort in this whole review.

Second

Replace permanent inline confirmations with a toast

One shared component, used everywhere a save currently prints a permanent green line — fixes the "stale summary card" issue too, if the same event that fires the toast also invalidates the polling views instead of waiting out their own clock.

Third

Give Settings and History a real desktop layout

Purely visual, no data-model changes — widen the container and let Settings' three sections sit in a grid the way Dashboard's four already do.

Reviewed by walking the live app end to end (register, log one of each entry type, browse History, check Trends, adjust Settings) at both a 412×915 mobile viewport and a 1440×900 desktop viewport. Every finding above reflects something actually rendered during that walkthrough, not a generic checklist applied without looking.
